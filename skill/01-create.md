# /상세페이지 만들기

`TOOL.md`(고정 규격)를 먼저 읽는다. 아래 8단계를 순서대로 밟는다. 건너뛰지 않는다.

---

## 1. 프리셋 선택 ★ 먼저 한다

`presets/_index.md` 를 읽고 등록된 프리셋을 **전부** 보여준다.

```
어떤 블록 구조로 만들까요?

  1. hana-nongsusan   하나농수산형
     다크 히어로 → 라이트 정보 구간. 사진 비중 69%
     hook → opener → point ×2~3 → package
     수산물 · 신선식품 · 가공식품

  2. 새 구조 만들기
     레퍼런스 페이지가 있으면 /상세페이지 분석하기 로 먼저 프리셋을 등록합니다

번호로 골라 주세요.
```

- 프리셋이 2개 이상이면 전부 나열한다
- 사용자가 카테고리를 이미 말했으면 맞는 것을 **먼저** 보여주되 나머지도 함께 보여준다
- `2. 새 구조 만들기` 를 고르면 `03-analyze.md` 로 넘어간다. 등록이 끝나면 여기로 돌아온다

고른 뒤 `presets/<id>/PRESET.md` 를 읽는다. **이후 모든 수치는 여기서 가져온다.**

```
고정 규격(TOOL.md)   여백 균등 · 줄맞춤 · 사진 선택 · 크롭 · 대비비 하한 · 법규
프리셋(PRESET.md)    캔버스 · 색 · 폰트 · 타이포 수치 · 블록 y 좌표 · 시퀀스

충돌하면 고정 규격이 이긴다.
```

## 2. 범위 확정

```
플랫폼       네이버 스마트스토어 / 쿠팡 / 카페24 / 자사몰
카테고리     식품 / 화장품 / 패션 / 가전 …
캔버스 폭     프리셋 기본값. 플랫폼이 다르면 사용자에게 확인
```

**식품이면** `TOOL.md` 6장(광고 금지 표현)을 이 시점에 통째로 읽는다.

## 3. 인터뷰

**사실만 받는다.** 추측으로 채우지 않는다. 모르는 항목은 "모름"으로 두고 카피에서 뺀다.

```
상품    정확한 상품명 · 원산지 · 중량/수량 옵션 · 가격
공정    만드는 과정과 순서 (배지의 재료가 된다)
상태    손질 범위 · 보관 온도 · 받는 시점의 상태
소재    사진 폴더 경로 · 인증서 · 시험성적서 · 기존 카피
```

참고 자료(판매글·경쟁사 링크·인증서)를 받으면 `INTERVIEW.md` 의
**참고 자료 입력란**에 원문 그대로 붙여 넣고, 거기서 사실을 추출해 표로 만든다.

**묻지 않는 것** — 플랫폼 입력 폼이 처리한다 (`TOOL.md` 6-9절)
```
택배사 · 배송 소요일 · 아이스박스 · 아이스팩 개수 · 제주도서 · 유통기한 · 교환반품
```

## 4. 사진 인벤토리

사진 폴더를 받으면 **전부 훑어보고** 분류한다. 컨택트시트로 한 번에 본다.

```
원물·벌크 / 손 스케일컷 / 포장·소분 / 조리·활용 / 공정
```

각 사진의 크롭 후 사용 가능 폭을 계산한다.
```python
cw = min(w, int(h / 목표비율))        # 목표비율 = 높이÷폭
배율 = (캔버스폭 × DPR) / cw          # 1.4 초과면 제외
```

필요 장수를 알린다. 프리셋 블록 수 × 2 가 기준.

## 5. 블록 선택 + 소구 축 배정

프리셋의 블록 시퀀스에서 쓸 것을 고른다.

```
point 개수는 소재가 결정한다. 증거 사진이 없는 축은 쓰지 않는다
축이 서로 겹치면 안 된다 (출처 / 맛 / 조리 / 보관 …)
```

## 6. 기획안

`examples/woolenggi/PLAN.md` 를 형식 참고로 쓴다. 반드시 담을 것:

```
사용한 프리셋 ID
블록별 y 좌표표 (여백까지 숫자로)
카피 전문 + 줄 폭 검산
사진 배정 + 멘트 연관성 + 크롭 object-position
법규 검사 결과 (항목별 건수)
합격 기준 — 전부 수치로
```

**합격 기준을 수치로 못 쓰면 기획이 덜 된 것이다.** 8단계에서 채점이 안 된다.

## 7. HTML/CSS → 렌더

`presets/<id>/blocks/` 를 작업 폴더로 복사해 시작한다.

```
base.css        토큰 (색·폰트·여백)
point.css       point 블록 공통
block-*.html    블록별 레이아웃
render.sh       headless Chrome 렌더
```

**폰트 계수를 먼저 확인한다.** 프리셋과 다른 폰트를 쓰면 `k1`·`k2` 를 다시 재야 한다.
```
font-size = 목표잉크 ÷ k1
span top  = 목표잉크top − k2 × font-size
```

하이라이트가 붙는 본문은 각 줄을
`display:inline-block; height:행pitch; line-height:행pitch` 로 두고 라인박스째 배치한다.

```bash
./render.sh out
```

## 8. 자체 테스트

```bash
python3 scripts/qa.py out/ --palette <프리셋 색상>
```

**그리고 PNG를 직접 연다.** 스크립트가 못 잡는 것:
```
사진이 멘트와 맞는가
피사체가 프레임 한가운데 있는가
텍스트가 피사체를 가리지 않는가
배경 구조물(테두리·선반)이 화면을 먹지 않는가
```

`TOOL.md` 10장 체크리스트를 전수 대조한다.
실패 항목은 고치고 **그 블록만** 다시 렌더한다.

## 프리셋을 고쳐 쓴 경우

작업 중 프리셋 값을 바꿨다면 **둘 중 하나**를 한다.

```
이 상품에만 해당     PLAN.md 에 "프리셋 재정의" 절로 기록. 프리셋은 건드리지 않는다
모든 상품에 해당     presets/<id>/PRESET.md 를 갱신하고 9장 결정사항에 이유를 남긴다
```
