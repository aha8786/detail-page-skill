# /상세페이지 분석하기

레퍼런스 상세페이지를 분석해 **구조 파일(프리셋)로 저장한다.**
이미지는 만들지 않는다. 나중에 `/상세페이지 만들기` 에서 골라 쓸 자산을 쌓는 작업이다.

```
/상세페이지 분석하기   분석 → 구조 파일만 저장      ← 자산 등록이 목적
/블록카피하기         분석 → 바로 렌더 → PNG 1장   ← 결과물이 목적
```

지금 당장 PNG 가 필요하면 `02-block-copy.md` 로 간다.

---

## 0. 받을 것

```
필수   상세페이지 이미지 (전체 한 장 또는 블록별로 잘린 여러 장) 또는 URL
선택   카테고리 (식품이면 법규 관점 기록이 붙는다)
선택   프리셋 ID 와 표시명 (안 주면 제안한다)
```

## 1. 블록 쪼개기

긴 이미지 한 장이면 블록 경계에서 자른다.

```bash
python3 scripts/measure.py page.png --target-width 610 --segment
```

배경색만 있는 행이 블록 경계다. 안 잡히면 명도 전환 지점과
사진↔텍스트 전환 지점을 눈으로 찾아 수동으로 자른다.

조각을 `ref-01.png`, `ref-02.png` … 로 저장한다.

## 2. 블록별 측정

조각마다 돌린다.

```bash
python3 scripts/measure.py ref-01.png --target-width 610
python3 scripts/measure.py ref-01.png --colors
```

조각마다 **9항목**을 기록한다. 기록 위치는 `presets/<새 id>/references/ANALYSIS.md`.
작성 예시는 `presets/hana-nongsusan/references/ANALYSIS.md`.

```
1. 블록 판정      어느 블록 ID인가, 무슨 일을 하나
2. 전체 구조      위→아래 요소 순서, 층 비율 (사진 몇 %, 텍스트 몇 %)
3. 이미지 요소    개수·배치·비율·모서리·성격
4. 텍스트 요소    계층별 잉크높이·행 pitch·굵기·색·정렬·줄당 글자수
5. 간격           요소 사이 여백, 블록 상하 패딩, 여백 리듬
6. 색             HEX + 각 용도
7. 시선 흐름      처음 눈이 닿는 곳 → 순서 → 그 순서를 만드는 장치
8. 가져올 것 / 버릴 것
9. 법규 관점      금지 표현이 있으면 표시 (그대로 베끼지 않도록)
```

**모든 수치는 원본 px 과 목표 캔버스 환산값을 함께 적는다.**
레퍼런스마다 캡처 배율이 다르므로 원본 px 은 그대로 못 쓴다.

## 3. 구조 파악

```
전체 길이 (스크롤 깊이)
사진 비중 vs 텍스트 비중 vs 여백 비중
블록별 높이
명도 리듬 (다크/라이트 전환 지점)
정렬 패턴 (구간별로 바뀌는가)
대비비 (대제목 : 본문)
```

## 4. 공통 패턴 추출 ★ 프리셋의 뼈대

블록 3개 이상에서 **반복되는 값**을 찾는다.
반복되면 토큰으로 승격, 한 번뿐이면 블록 전용으로 남긴다.

```
반복되는 블록 순서         → 블록 시퀀스
반복되는 여백 값           → 여백 스케일
반복되는 잉크높이           → 타이포 스케일
반복되는 색                → 색상 토큰
반복되는 강조 형태          → 형태-역할 매핑
반복되는 사진:텍스트 비율
```

**폰트 판별** — 잉크/pitch 비율을 블록마다 비교한다.
```
전 블록 같은 비율   폰트 1종, 웨이트만 다름
비율이 갈림         폰트 2종 이상
~0.72              일반 고딕 (Pretendard · Noto Sans KR)
0.95+              헤비 스퀘어 고딕 (Paperlogy · Black Han Sans · GmarketSans)
```

## 5. 결함 걸러내기 ★ 그대로 베끼지 않는다

`TOOL.md` 고정 규격과 충돌하는 값은 **버린다.** 버린 것을 전부 기록한다.

```
같은 색을 여러 톤으로 흘림        → 하나로 통일
본문 상하 여백이 다름             → 균등하게
본문 모바일 실효 14px 미만        → 상향
면책을 본문보다 작게              → 같은 크기, 색만 낮춤
줄 길이가 들쭉날쭉                → 의미 단위로 다시 끊음
줄 끝 쉼표 · 어절 중간 끊김       → 다시 끊음
```

## 6. 프리셋 저장

```
presets/<새 id>/
  PRESET.md                 아래 8장 구성
  references/ANALYSIS.md    2단계 측정 기록
  blocks/                   블록 HTML·CSS·render.sh
  preview/                  (선택) 레퍼런스 축소판
```

`PRESET.md` 구성은 `presets/hana-nongsusan/PRESET.md` 를 그대로 따른다.
```
0 출력 · 1 레이아웃 · 2 타이포 · 3 색 · 4 강조 형태
5 블록 시퀀스 · 6 블록별 좌표 · 7 레퍼런스를 따르지 않은 지점 · 8 적용 사례
```

**7장을 반드시 채운다.** 5단계에서 버린 값을 전부 적는다.
안 적으면 다음 사람이 "왜 레퍼런스와 다르지?" 하고 되돌린다.

`blocks/` 템플릿은 측정한 y 좌표로 작성한다. **렌더해서 검증한다.**
```bash
./render.sh out
python3 scripts/measure.py out/블록.png --target-width <캔버스 폭>
```
원본 측정값과 ±3px 안이면 템플릿이 맞게 짜인 것이다.
검증용 렌더일 뿐 **결과물이 아니다.** `out/` 은 지우거나 `preview/` 로만 남긴다.

## 7. 카탈로그 등록

`presets/_index.md` 표에 한 줄 추가한다.

```
| <id> | <표시명> | <성격 한 줄> | <블록 시퀀스> | <맞는 카테고리> | <근거> |
```

ID 규칙:
```
소문자 · 하이픈 · 영문만        폴더명으로 쓴다
출처나 성격을 담는다            hana-nongsusan · dark-hero-evidence
```

## 8. 보고

작업이 끝나면 사용자에게 알린다.

```

블록 시퀀스   hook → opener → point ×N → package
캔버스        610 × DPR2
색            #XXXXXX / #XXXXXX / #XXXXXX
폰트          <폰트> (k1=0.00 k2=0.00)

레퍼런스에서 버린 값 N건
  - <버린 값> → <고친 값>  (사유)

```

## 진단 리포트가 따로 필요하면

프리셋 등록 없이 **진단만** 원한다고 하면 1~5단계만 돌리고 아래 형식으로 낸다.

```markdown
# 상세페이지 진단 — <출처>

## 한 줄 결론
<가장 크게 손해 보고 있는 지점 하나>

## 수치 요약
| 항목 | 실측 | 기준 | 판정 |

## 치명   법규 위반 · 모바일 가독성 미달 · 첫 화면 정체 불명
## 중요   소구 축 중복 · 증거 없는 주장 · 사진-멘트 불일치
## 사소   여백 불균등 · 줄 길이 편차 · 색 톤 분열

## 그대로 둘 것
<잘 된 부분. 고치다가 망가뜨리지 않게 명시>
```

**잘 된 부분을 반드시 적는다.** 안 적으면 다음 개정에서 날아간다.
