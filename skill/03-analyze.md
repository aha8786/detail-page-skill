# /상세페이지 분석하기

레퍼런스 상세페이지 **전체**를 분석해 **새 프리셋으로 등록**한다.
진단 리포트는 그 과정에서 같이 나온다.

```
/상세페이지 분석하기   페이지 전체 → 새 프리셋 등록 (+ 진단 리포트)
/블록카피하기         블록 1개   → 기존 프리셋에 추가·교체
```

---

## 0. 받을 것

```
상세페이지 이미지 (전체 한 장 또는 블록별로 잘린 여러 장) 또는 URL
카테고리 (식품이면 법규 검사가 붙는다)
프리셋으로 등록할지, 진단만 할지
```

**진단만 원하면** 1~3단계 + 7단계만 하고 리포트를 낸다.
**프리셋 등록까지 가면** 전 단계를 밟는다.

## 1. 블록 쪼개기

긴 이미지 한 장이면 블록 경계에서 자른다.

```bash
python3 scripts/measure.py page.png --target-width 610 --segment
```

배경색만 있는 행이 블록 경계다. 경계가 안 잡히면 명도 전환 지점과
사진↔텍스트 전환 지점을 눈으로 찾아 수동으로 자른다.

각 조각을 `ref-01.png`, `ref-02.png` … 로 저장한다.

## 2. 블록별 측정

조각마다 돌린다.

```bash
python3 scripts/measure.py ref-01.png --target-width 610
python3 scripts/measure.py ref-01.png --colors
```

`02-block-copy.md` 2장의 **9항목**을 조각마다 기록한다.
기록 위치는 `presets/<새 id>/references/ANALYSIS.md`.

## 3. 구조 진단

```
전체 길이 (스크롤 깊이)
사진 비중 vs 텍스트 비중 vs 여백 비중
블록별 높이
명도 리듬 (다크/라이트 전환 지점)
정렬 패턴 (구간별로 바뀌는가)
```

**판정 기준**
```
전체 길이 6000px 초과       후반부 이탈 위험
사진 비중 50% 미만          신선식품·패션이면 설득력 부족
한 블록 3000px 초과         플랫폼 업로드·로딩 문제
명도 전환 0회               단조로움. 구간 구분이 안 됨
```

## 4. 공통 패턴 추출 ★ 프리셋의 뼈대

블록 3개 이상에서 **반복되는 값**을 찾는다. 반복되면 토큰, 한 번뿐이면 블록 전용.

```
반복되는 블록 순서
반복되는 사진:텍스트 비율
반복되는 여백 값          → 여백 스케일로 승격
반복되는 잉크높이          → 타이포 스케일로 승격
반복되는 색               → 색상 토큰으로 승격
반복되는 강조 형태         → 형태-역할 매핑으로 승격
대비비 (대제목 : 본문)
```

**폰트 판별** — 잉크/pitch 비율을 블록마다 비교한다.
전 블록이 같은 비율이면 폰트 1종, 다르면 2종 이상이다.

## 5. 결함 걸러내기 ★ 그대로 베끼지 않는다

`TOOL.md` 고정 규격과 충돌하는 값은 **버린다.** 버린 것을 기록에 남긴다.

```
같은 색을 여러 톤으로 흘림        → 하나로 통일
본문 상하 여백이 다름             → 균등하게
본문 모바일 실효 14px 미만        → 상향
면책을 본문보다 작게              → 같은 크기, 색만 낮춤
줄 길이가 들쭉날쭉                → 의미 단위로 다시 끊음
줄 끝 쉼표 · 어절 중간 끊김       → 다시 끊음
```

## 6. 프리셋 등록

```
presets/<새 id>/
  PRESET.md                 아래 8장 구성으로 작성
  blocks/                   블록 HTML·CSS·render.sh
  references/ANALYSIS.md    2단계 측정 기록
  preview/*.png             렌더 축소판
```

`PRESET.md` 구성은 `presets/hana-nongsusan/PRESET.md` 를 그대로 따른다.
```
0 출력 · 1 레이아웃 · 2 타이포 · 3 색 · 4 강조 형태
5 블록 시퀀스 · 6 블록별 좌표 · 7 레퍼런스를 따르지 않은 지점 · 8 적용 사례
```

**7장을 반드시 채운다.** 레퍼런스에서 뭘 버렸는지 안 적으면
다음 사람이 "왜 레퍼런스와 다르지?" 하고 되돌린다.

`presets/_index.md` 표에 한 줄 추가한다.
```
| <id> | <표시명> | <성격 한 줄> | <블록 시퀀스> | <맞는 카테고리> | <근거> |
```

## 7. 진단 리포트

프리셋 등록과 별개로 리포트를 낸다. 진단만 요청받았을 때는 이것만 낸다.

### 타이포
```
본문 잉크높이 × (화면폭 ÷ 캔버스폭) ≥ 14px     모바일 실효 가독성
대제목 : 본문 비율                              히어로 3:1 이상 / 본문 2:1 이상
줄 끊김                                        어절 중간 · 줄 끝 쉼표 · 한 줄 안 문장 전환
줄 길이 편차                                    3자 초과면 지적
```

### 여백·정렬
```
본문 블록 상하 여백이 같은가
좌우 여백이 블록마다 일정한가
정렬이 구간별로 일관된가
```

### 색
```
색이 몇 개인가              6개 초과면 산만
같은 역할에 다른 톤          결함
강조 색이 한 개인가
면책이 본문보다 작지 않은가
```

### 사진
```
사진이 바로 옆 멘트의 내용과 맞는가
크롭 후 피사체가 프레임 한가운데 있는가
텍스트가 피사체를 가리지 않는가
배경 구조물(테두리·선반)이 화면을 먹지 않는가
같은 성격 사진이 2장 연속되지 않는가
```

### 소구 축
```
각 블록이 무슨 주장을 하는지 한 줄로 적는다
축이 겹치는 블록 → 합친다
증거 사진 없이 주장만 있는 블록 → 사진을 붙이거나 뺀다
첫 화면에서 상품 정체가 3초 안에 잡히는가
```

### 법규 (식품)
`TOOL.md` 6장 전 항목 전수 대조. 발견 시 원문 인용 + 대체안.

### 리포트 형식
```markdown
# 상세페이지 분석 — <상품명 또는 출처>

## 한 줄 결론
<가장 크게 손해 보고 있는 지점 하나>

## 수치 요약
| 항목 | 실측 | 기준 | 판정 |

## 치명 (지금 고쳐야 함)
법규 위반 · 모바일 가독성 미달 · 첫 화면 정체 불명

## 중요 (전환율에 영향)
소구 축 중복 · 증거 없는 주장 · 사진-멘트 불일치

## 사소 (여유 될 때)
여백 불균등 · 줄 길이 편차 · 색 톤 분열

## 그대로 둘 것
<잘 된 부분. 고치다가 망가뜨리지 않게 명시>

## 프리셋 등록 결과
등록 ID · 블록 시퀀스 · 버린 값 목록
```

**잘 된 부분을 반드시 적는다.** 안 적으면 다음 개정에서 날아간다.

## 끝나면

프리셋을 등록했으면 `/상세페이지 만들기` 로 넘어간다.
1단계 프리셋 선택 목록에 방금 만든 것이 떠 있어야 한다.
