# /상세페이지 분석하기

완성된 상세페이지를 진단하고 **고칠 곳을 우선순위로** 내놓는다.
내 페이지든 경쟁사 페이지든 같은 절차.

`/블록카피하기` 와 다른 점: 저쪽은 **가져오기**(제작용), 이쪽은 **평가**(리포트).

---

## 0. 받을 것

```
상세페이지 이미지 전체 또는 URL
카테고리 (식품이면 법규 검사가 붙는다)
```

긴 이미지 한 장이면 블록 경계에서 잘라 놓고 시작한다.

## 1. 구조 해부

```bash
python3 scripts/measure.py 페이지.png --target-width 610 --segment
```

```
블록 경계와 각 블록 높이
전체 길이 (스크롤 깊이)
사진 비중 vs 텍스트 비중 vs 여백 비중
명도 리듬 (다크/라이트 전환 지점)
```

**진단 기준**
```
전체 길이 6000px 초과       후반부 이탈 위험
사진 비중 50% 미만          신선식품·패션이면 설득력 부족
한 블록 3000px 초과         플랫폼 업로드·로딩 문제
명도 전환 0회               단조로움. 구간 구분이 안 됨
```

## 2. 소구 축 점검

각 블록이 무슨 주장을 하는지 한 줄로 적는다.

```
축이 겹치는 블록이 있는가          → 하나로 합친다
증거 사진 없이 주장만 있는 블록     → 사진을 붙이거나 뺀다
첫 화면에서 상품 정체가 3초 안에 잡히는가
```

## 3. 타이포 진단

```
본문 잉크높이 × (화면폭 ÷ 캔버스폭) ≥ 14px   모바일 실효 가독성
대제목 : 본문 비율                            히어로 3:1 이상 / 본문 2:1 이상
줄 끊김                                      어절 중간 끊김 · 줄 끝 쉼표 · 한 줄 안 문장 전환
줄 길이 편차                                  3자 초과면 지적
```

## 4. 여백·정렬 진단

```
본문 블록 상하 여백이 같은가
좌우 여백이 블록마다 일정한가
정렬이 구간별로 일관된가 (몰입 구간 가운데 / 읽기 구간 왼쪽)
```

## 5. 색 진단

```bash
python3 scripts/measure.py 페이지.png --colors
```

```
색이 몇 개인가          6개 초과면 산만
같은 역할에 다른 톤      예: 네이비가 3톤 → 결함
강조 색이 한 개인가
면책·고지가 본문보다 작지 않은가   작으면 분쟁 시 불리
```

## 6. 사진 진단

```
사진이 바로 옆 멘트의 내용과 맞는가
크롭 후 피사체가 프레임 한가운데 있는가
텍스트가 피사체를 가리지 않는가
배경 구조물(테두리·선반)이 화면을 먹지 않는가
같은 성격 사진이 2장 연속되지 않는가
```

## 7. 법규 검사 (식품)

`TOOL.md` 6장 전 항목을 **전수 대조**한다. 발견 시 원문을 인용하고 대체안을 함께 낸다.

```
6-1  질병 예방·치료 효능
6-2  의약품 오인
6-3  건강기능식품 오인  ← `~에 도움이 되며` 문형 자체가 금지
6-4  거짓·과장
6-5  소비자 기만
6-6  무인증 단어
6-7  후기 효능 암시
6-8  타사 비방
6-10 영양강조표시       ← `풍부`·`가득`은 기준치 충족 + 시험성적서 필요
```

## 리포트 형식

```markdown
# 상세페이지 진단 — <상품명>

## 한 줄 결론
<가장 크게 손해 보고 있는 지점 하나>

## 수치 요약
| 항목 | 실측 | 기준 | 판정 |

## 치명 (지금 고쳐야 함)
법규 위반 · 모바일 가독성 미달 · 첫 화면 정체 불명

## 중요 (전환율에 영향)
소구 축 중복 · 증거 없는 주장 · 사진-멘트 불일치

## 사소 (여유 될 때)
여백 불균등 · 줄 길이 편차 · 색 톤 분열

## 그대로 둘 것
<잘 된 부분. 고치다가 망가뜨리지 않게 명시>
```

**잘 된 부분을 반드시 적는다.** 안 적으면 다음 개정에서 날아간다.
