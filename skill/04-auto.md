# /알아서 만들기

내용만 받아서 **구조·디자인까지 전부 정해서** 상세페이지를 만든다.
프리셋을 고르지 않는다. 레퍼런스도 필요 없다.

```
/알아서 만들기       내용만 받는다. 구조·색·폰트·블록을 내가 정한다
/상세페이지 만들기    저장된 프리셋을 골라서 만든다
```

---

## 지켜야 할 선

```
알아서 한다      색 · 폰트 · 블록 구성 · 레이아웃 수치 · 카피 문장 · 사진 배정
알아서 안 한다    사실
```

**사실을 지어내지 않는다.**
```
원산지 · 생산방식 · 중량 · 가격 · 공정 · 보관온도 · 인증 · 성분
```
자료에 없으면 그 항목만 묻거나 카피에서 뺀다. 그럴듯하게 채우지 않는다.

`TOOL.md` 고정 규격은 그대로 적용한다. 여백 균등·줄맞춤·사진 선택·크롭·법규는 협상 대상이 아니다.

---

## 1. 상품 글을 요청한다 ★ 먼저 묻는다

이 명령을 고르면 **다른 말을 하기 전에** 이것부터 요청한다.

```
상품에 대한 글을 주세요.

  판매글 · 블로그 글 · 상품 설명서 · 메모 — 형식은 상관없습니다
  사진 폴더 경로도 함께 주시면 좋습니다

글에서 사실을 뽑아 상세페이지를 만들겠습니다.
```

받으면 원문을 `INTERVIEW.md` **참고 자료 입력란**에 그대로 붙여 넣는다.
원문을 보존한다. 요약해서 넣지 않는다. 나중에 사실 검증의 근거가 된다.

글 대신 URL·사진만 줘도 진행한다. 다만 **글이 있을 때 결과가 가장 좋다.**
글이 전혀 없으면 사실이 부족해 3단계 질문이 길어진다.

## 2. 카테고리 판정 ★ 법규 모듈이 여기서 결정된다

글에서 카테고리를 **추정하고 사용자에게 확인받는다.** 추정만으로 넘어가지 않는다.

```
글을 보니 <카테고리> 로 보입니다. 맞나요?

  맞으면 <해당 법규> 광고 규제를 적용해 카피를 씁니다.
  다르면 알려 주세요.
```

| 단서 | 카테고리 | 적용 모듈 |
|---|---|---|
| 먹는다 · 맛 · 식감 · 조리 · 산지 · 유통기한 | **식품** | `TOOL.md` 6장 (전체) |
| 바른다 · 피부 · 보습 · 세안 · 용량 ml | **화장품** | `TOOL.md` 6-11절 |
| 기능성 인정 · 건강기능식품 마크 · 1일 섭취량 | **건강기능식품** | `TOOL.md` 6-12절 |
| 착용 · 사이즈 · 소재 · 세탁 | **패션·잡화** | `TOOL.md` 6-13절 |
| 전압 · 소비전력 · KC 인증 · A/S | **가전·공산품** | `TOOL.md` 6-13절 |

**판정이 안 되면 묻는다.** 규제 카테고리를 잘못 잡으면 카피 전체를 다시 써야 한다.

판정 결과를 `INTERVIEW.md` 맨 위에 기록한다.

## 3. 사실 추출

글에서 뽑을 수 있는 것을 전부 뽑아 표로 만든다. **출처와 검증 상태를 함께 적는다.**

| 항목 | 값 | 출처 | 검증 |
|---|---|---|---|
| 상품명 | | 자료 01 | ✅ / ⬜ |
| 카테고리 | | 2단계 확인 | ✅ |
| 원산지·제조국 | | | |
| 중량·용량·옵션 | | | |
| 가공·손질 상태 | | | |
| 보관 조건 | | | |
| 활용·사용법 | | | |
| 인증·성적서 | | | |

```
✅   글에 명시돼 있다. 카피에 쓸 수 있다
⬜   글에 없다. 4단계에서 묻거나 카피에서 뺀다
```

## 4. 부족한 것만 묻기 ★ 질문을 최소로

**세 종류만 묻는다.**

```
1. 법규가 걸리는 것        원산지 · 생산방식 · 보관온도 · 인증 · 성분 함량
2. 사진으로 확인 안 되는 것  중량 · 가격 · 공정 순서
3. 자료끼리 충돌하는 것     예: 글은 "냉장", 사진은 아이스박스
```

**묻지 않는 것** — 추측해도 되는 영역
```
색 · 폰트 · 블록 개수 · 소구 축 · 카피 문장 · 사진 배정 · 레이아웃
```

**절대 묻지 않는 것** — 플랫폼 폼이 처리 (`TOOL.md` 6-9절)
```
택배사 · 배송 소요일 · 아이스박스 · 아이스팩 · 제주도서 · 유통기한 · 교환반품
```

질문은 **한 번에 모아서** 한다. 한 개씩 나눠 묻지 않는다.

## 5. 사진 인벤토리 → 블록 구성 역산

사진을 전부 훑고 분류한다. **블록 구성은 사진이 결정한다.**

```
분류                        나올 수 있는 블록
───────────────────────────────────────────
손 스케일컷 · 원물 클로즈업    hook        (크기와 정체를 동시에 보여줌)
텍스처가 화면을 채우는 컷      opener      (오버레이 깔고 챕터 표지로)
공정·작업 현장               point(공정)
조리·활용 완성컷 2장 이상      point(활용도)
포장·소분                    point(손질) 또는 package
인증서·시설                   trust
```

**증거 사진이 없는 축은 만들지 않는다.** 글만 있는 주장은 안 쓴다.

해상도 판정도 같이 한다.
```python
cw = min(w, int(h / 목표비율))
배율 = (캔버스폭 × DPR) / cw        # 1.4 초과면 제외
```

결과를 사용자에게 보고한다.
```
사진 N장 확인. 블록 M개를 만들 수 있습니다.
  hook      <파일>
  point 1   <주제> — <파일> + <파일>
  point 2   <주제> — <파일> + <파일>
  package   <파일>

쓸 수 없는 사진 K장 (해상도 미달 / 배경 충돌)
```

## 6. 디자인 방향 결정 ★ 여기가 "알아서"의 핵심

### ⓐ 구조 유형 판정 — 블록 구성이 여기서 나온다

**기존 프리셋을 베끼지 않는다.** 글의 소구 성격에서 구조를 역산한다.

| 소구 성격 | 신호 | 구조 유형 | 블록 구성 |
|---|---|---|---|
| 검증 가능한 사실이 많다 | 산지·공정·인증·수치가 3개 이상 | **증거 나열형** | 후킹 → 챕터표지 → 포인트 ×2~3 → 마무리 |
| 차별점이 "불편의 제거" | 손질완료·간편·시간 단축 | **노동 제거형** | 전면 히어로 → 수치 스트립 → 수고 제거 → 활용 → 마무리 |
| 감정·추억·분위기가 핵심 | 향·기억·계절·장면 묘사 | **정서형** | 전면 히어로 → 정서 전면 → 활용 → 마무리 |
| 수치가 결정적 | 용량·성능·함량 비교 | **스펙형** | 후킹 → 수치 스트립 → 비교표 → 마무리 |

**글이 짧으면 블록도 적게.** 소구가 2개인데 포인트를 3개 만들면 억지로 채우게 된다.
```
소구 2개  →  블록 4~5개
소구 3개  →  블록 5~6개
소구 4개+ →  블록 6~8개
```

### ⓑ 형태 선택 — 배지·스트립·그리드 중 무엇을 쓸지

**형태는 내용이 정한다.** 전부 쓰지 않는다. 고른 것만 쓴다.

| 조건 | 형태 | 스펙 |
|---|---|---|
| 검증 가능한 **공정 3단계** | 원형 배지 | 시간 순서로 배치. 라벨 글자 수 통일 |
| 결정적 **수치 2~3개** | 숫자 스트립 | 숫자 크게 + 라벨 작게 + 세로 구분선 |
| 병렬 **사례 2~4개** | 그리드 | 가로 분할 + 칸마다 라벨 |
| 블록이 **6개 이상** | 번호 필(pill) | 블록이 적으면 번호가 의미 없다 |
| 본문 **3줄 이상** + 강조할 사실구 | 형광펜 | 본문 2줄 이하면 강조 대상이 없다 |
| 짧은 선언 1줄 | 각진 강조 바 | 3줄 크레셴도 가운데 줄에만 |

**선택한 형태끼리 역할이 겹치면 안 된다.** 배지와 스트립을 같이 쓰지 않는다.

### ⓒ 레이아웃 치수 산출

**좌우 여백은 분할 수가 정한다.**
```
분할 없음       여백 48   콘텐츠 514
2분할           여백 44   콘텐츠 522   칸 = (522 − 간격10) ÷ 2 = 256
3분할           여백 40   콘텐츠 530   칸 = (530 − 간격13×2) ÷ 3 = 168
4분할 이상       여백 32   칸 = (546 − 간격×(n−1)) ÷ n
```

**타이포는 본문에서 역산한다.**
```
본문 잉크 = 캔버스 폭 × 0.036 ~ 0.040
            글이 길면 0.036, 짧으면 0.040 (여유가 있으므로 키운다)

섹션 제목 = 본문 × 2.1 이상       ← 대비비 하한 2:1
히어로 대제목 = 히어로 서브 × 3.0 이상   ← 하한 3:1. 4.0~4.6 권장
숫자 = 섹션 제목보다 크게         ← 스트립의 주인공이므로
라벨 = 숫자 × 0.28~0.32
```

**히어로 대제목 크기는 글자 수가 정한다.**
```
2줄이 각 4~5자   캔버스 폭의 11%  (짧아서 작아도 눌린다)
2줄이 각 6~7자   캔버스 폭의 12%
한 줄이 8자 이상  폭 검산으로 역산. 콘텐츠 폭을 넘으면 줄인다
```

### ⓓ y 좌표 누적 산출

**위에서부터 더해 내려간다.** 좌표를 찍는 게 아니라 쌓는다.

```
y = 0
y += 상단 여백
각 요소마다:
    요소 잉크 top = y
    y += 잉크높이
    y += 다음 요소까지 여백
y += 하단 여백
블록 높이 = y
```

**텍스트 배치 변환** (line-height:1 기준)
```
font-size = 잉크높이 ÷ k1
span top  = 잉크 top − k2 × font-size
```

**본문 블록은 라인박스로 배치한다.** 하이라이트 띠 높이가 행간과 맞아야 한다.
```
라인박스 높이 = 행 pitch
ink offset = (행pitch − font-size) ÷ 2 + k2 × font-size
```

**본문 상하 여백은 반드시 같게.** (`TOOL.md` 1장 고정 규격)
```
여백 = (앞 요소 끝 ~ 뒤 요소 시작 간격 − 라인박스 총높이) ÷ 2
```

### ⓔ 사진 비중 — 블록 높이를 여기서 결정

```
수산물·신선식품    60~70%
가공식품          50~60%
패션·잡화         70% 이상
화장품            50~60%
가전·공산품        40~50%
```

블록 높이 = 텍스트 영역 + 여백 + **(전체 × 목표 사진 비중)** 으로 역산한다.
사진 높이를 먼저 정하고 나머지를 텍스트에 배분하는 게 아니다.

### ⓕ 명도 리듬

```
몰입 구간(히어로·정서)   다크
정보 구간(설명·안내)     라이트

블록 5개 이상이면 중간에 다크를 한 번 더 넣는다
→ 다크 → 라이트 → 라이트 → 다크 → 라이트 → 라이트
전환이 1회뿐이면 후반부가 단조로워진다
```

### 팔레트 — 3색으로 짠다

```
1. 사진에서 지배색을 뽑는다
   python3 scripts/measure.py <대표사진> --colors

2. 다크 베이스를 정한다
   피사체가 따뜻한 색(살구·갈색·주황)  →  차가운 다크 또는 중립 차콜
   피사체가 차가운 색(청록·회색·흰색)  →  따뜻한 다크 또는 깊은 네이비
   → 피사체와 배경이 보색/온도 대비를 이루게 한다

3. 라이트 베이스를 정한다
   다크 베이스와 같은 계열의 아주 밝은 톤
   순백(#FFFFFF)보다 살짝 틀어 주면 사진이 덜 뜬다

4. 보조 회색 1개
   라이트 베이스와 같은 온도. 면책·아이브로우 전용
```

```
색 3개가 끝. 빨강·노랑 강조 금지.
강조는 크기 대비 + 다크/라이트 반전으로만.
```

### 폰트

```
한글 헤비 스퀘어 고딕 1종. 웨이트만 바꾼다.
Paperlogy / Black Han Sans / GmarketSans 중 설치된 것

제목 Black(900) · 서브·라벨 Bold(700) · 본문 SemiBold(600) · 면책 Medium(500)
```

프로브 렌더로 `k1`·`k2` 를 **반드시 실측**한다. 폰트마다 다르다.
```
k1 = 잉크높이 ÷ font-size
k2 = (잉크 top − span top) ÷ font-size       (line-height:1 기준)
```

**사용자가 바꾸라고 하면 바꾼다.** "알아서"는 기본값이지 강제가 아니다.

### ★ 이 보고는 건너뛰지 않는다

```
사진이 있어 렌더로 간다        → 보고하고 승인받은 뒤 8단계로
사진이 없어 샷리스트로 간다     → 보고하고 승인받은 뒤 샷리스트를 낸다
```

**렌더를 못 하는 경우에도 디자인 보고는 반드시 한다.**
샷리스트의 배경색·금지색·구도 조건이 전부 여기서 정한 팔레트와 블록 구성에서 나온다.
보고 없이 샷리스트만 내면 사용자가 그 조건이 왜 그런지 검증할 수 없고,
팔레트가 틀렸을 때 **촬영을 다 하고 나서야 알게 된다.**

사진이 없을 때는 보고 끝에 한 줄을 덧붙인다.
```
사진이 없어 렌더는 못 합니다. 이 방향으로 촬영 샷리스트를 내겠습니다.
```

## 7. 카피 작성

`TOOL.md` 7장 줄맞춤 규칙으로 직접 줄을 끊는다.

```
어미        존댓말 평서형 고정
대제목      2줄. 2행 끝을 상품명으로 닫아 각인
본문        2~4줄. 줄 간 글자 수 차이 3자 이내
하이라이트   본문의 35~45%. 검증 가능한 사실·차별점에만
```

**3단계 표에서 ✅ 인 항목만 카피에 쓴다.** ⬜ 는 쓰지 않는다.

2단계에서 판정한 카테고리의 법규 모듈로 **이 시점에** 전수 검사한다.

## 8. 기획안 → 렌더 → 테스트

`01-create.md` 6~8단계와 같다.

```
기획안    블록별 y 좌표 · 카피 전문 · 사진 배정 · 법규 검사 · 합격 기준
렌더      ./render.sh out
테스트    python3 scripts/qa.py out/ --palette <정한 색상>
          + PNG 직접 열어 육안 확인
```

### ★ 프리셋 템플릿을 복사하지 않는다

```
✗ presets/<id>/blocks/ 를 복사해 색만 바꾼다
✓ 6단계에서 산출한 y 좌표·분할 폭·형태로 HTML 을 새로 쓴다
```

**복사하면 구조가 그대로 따라온다.** 색을 바꿔도 같은 페이지가 나온다.
기존 구조를 쓰고 싶으면 이 명령이 아니라 `/상세페이지 만들기` 를 쓴다.

`base.css` 는 토큰 선언(색·폰트·여백)만 새로 쓰고,
블록 HTML 은 ⓓ에서 누적 산출한 좌표를 그대로 절대 배치한다.

렌더 전에 **k1·k2 를 프로브로 실측한다.** 폰트가 다르면 좌표가 전부 틀어진다.

## 9. 프리셋으로 저장할지 묻기 ★ 마지막

```
이번에 만든 디자인을 프리셋으로 저장할까요?

  1. 저장  — presets/<id>/ 에 구조를 저장합니다
            다음에 /상세페이지 만들기 에서 골라 쓸 수 있습니다
  2. 안 함 — 이번 결과물만 쓰고 끝냅니다
```

**저장을 고르면** `03-analyze.md` 6~7단계와 같은 형식으로 쓴다.
```
presets/<id>/PRESET.md              8장 구성
presets/<id>/blocks/                이번에 쓴 HTML·CSS
presets/<id>/references/ANALYSIS.md 레퍼런스가 없으므로 "자체 설계" 로 기록
                                    6단계 결정 근거를 그대로 옮긴다
presets/_index.md                   카탈로그 한 줄 추가
```

이게 쌓이면 다음부터는 `/상세페이지 만들기` 로 더 빨리 끝난다.

## 산출물

```
INTERVIEW.md   받은 글 원문 + 카테고리 판정 + 추출된 사실 표 + 질문/답변
PLAN.md        기획안 + 디자인 결정 근거 + 합격 기준
src/           HTML·CSS·사진·render.sh
output/        블록별 PNG + 전체 조립 미리보기
presets/<id>/  8단계에서 저장을 골랐을 때만
```

## 이 명령이 실패하는 경우

```
글도 사진도 없다          → 상품 글부터 요청한다. 아무것도 없으면 시작할 수 없다
사진이 없다              → 렌더 불가. 6단계 디자인 보고·승인은 그대로 하고
                           촬영 샷리스트를 대신 낸다. 보고를 건너뛰지 않는다
사실이 거의 없다          → 질문 목록을 내고 멈춘다. 지어내지 않는다
카테고리 판정이 안 된다    → 묻는다. 추정으로 넘어가면 법규 위반 위험
사진 해상도가 전부 미달    → 쓸 수 있는 장수를 알리고 블록 수를 줄인다
```
